# Plan 13-06: Privacy, Secret Redaction, And Storage Policies

## Objective

Add secret redaction that runs before any session content reaches summaries or writeback proposals. Define ignore patterns and retention policy via config. Ensure raw session data is never committed.

## Scope

### Secret redaction (`services/session_redaction.py`)

Implement `redact_session(normalized: NormalizedSession) -> NormalizedSession`.

Patterns to detect and replace with `[REDACTED:<type>]`:

| Pattern | Type label |
|---------|-----------|
| `sk-[A-Za-z0-9]{20,}` (OpenAI-style) | `api_key` |
| `Bearer [A-Za-z0-9._-]{10,}` | `bearer_token` |
| `Authorization: [^\n]+` in string fields | `auth_header` |
| `[A-Z_]{3,}=[A-Za-z0-9._~\-+/]{8,}` (.env-style) | `env_secret` |
| PEM blocks (`-----BEGIN ...-----`) | `pem_key` |
| `ghp_[A-Za-z0-9]{36}` (GitHub PAT) | `github_token` |
| `xoxb-[0-9]+-[A-Za-z0-9]+` (Slack token) | `slack_token` |

The redaction applies to: `messages`, `tool_calls`, `file_edits`, `commands_run`, `decisions_extracted`, `todos_extracted`, `errors_extracted`, `title`.

If a field contains a secret that cannot be isolated (e.g., binary or opaque encoded blob), set `redaction_incomplete = True` on the session. Sessions with `redaction_incomplete = True` get `summary_status = "redaction_incomplete"` and are excluded from writeback candidates.

### Configuration (`config/session-provider-config.yaml`)

```yaml
session_providers:
  enabled:
    - claude
    - codex
    - cursor
    - antigravity
  ignore_path_patterns:
    - "**/.env"
    - "**/.env.*"
    - "**/node_modules/**"
    - "**/.git/**"
  retention_days:
    claude: 365
    codex: 365
    cursor: 180
    antigravity: 180
  min_session_words:
    claude: 50
    codex: 50
    cursor: 20
    antigravity: 20
```

### Gitignore enforcement

Confirm and add `.gitignore` entries:
```
AIOS/staging/cursor-snapshots/
AIOS/staging/ai-history/
AIOS/staging/antigravity-snapshots/
AIOS/data/aios.db
```

These paths must not appear in `git status` after sync runs.

### Storage rules

- Raw session content (full message arrays): stored in `aios.db` only, never in files committed to git
- Summaries: `logs/summaries/` — excluded from git
- Vault writebacks: structured metadata notes only (see Plan 13-07)

## Standards

- Redaction runs in a pure function: no DB reads or writes inside `redact_session()`.
- Pattern list is configurable — new patterns can be added to `config/session-provider-config.yaml` without code changes.
- Sessions with `redaction_incomplete` are never silently dropped — they are stored with the flag and surfaced in `aios sessions status`.
