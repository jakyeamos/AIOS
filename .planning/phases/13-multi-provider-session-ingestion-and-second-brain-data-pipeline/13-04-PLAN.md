# Plan 13-04: Antigravity Provider Implementation

## Objective

Implement the Antigravity CLI `SessionProvider`. Discover sessions from the Gemini/Antigravity brain directories, detect file formats, extract safe operational metadata, and skip or pointer-store content that cannot safely be summarized.

## Scope

### Source discovery paths

Primary:
```
~/.gemini/antigravity-cli/brain/**
~/.gemini/antigravity-cli/plugins/**
~/.gemini/GEMINI.md
```

Secondary (scan for any config/log/cache/session files):
```
~/.gemini/**
~/.config/Antigravity/**
```

Platform-specific app support/config paths should be detected via `platform.system()` where applicable.

### Format detection

Before parsing, detect the file format:

| Detection method | Format |
|------------------|--------|
| Extension `.json` + valid JSON parse | JSON |
| Extension `.jsonl` + first line is valid JSON | JSONL |
| Extension `.db` / `.sqlite` / `.vscdb` + SQLite magic bytes | SQLite |
| Extension `.md` | Markdown |
| ASCII/UTF-8 text file | Plain text log |
| Other | Unknown binary |

Unknown binary files: store `{path, size, mtime, hash, format: "unknown_binary"}` as metadata. Skip content. Emit a `HealthWarning` in `health_check()`.

### Numeric directory session ID handling

Directories named with numeric IDs under `brain/` (e.g., `brain/1234567/`) are treated as session candidates. The directory name is the `provider_session_id`. Contents are inspected for the recognized formats above.

### Reasoning trace handling

Reasoning traces (chain-of-thought, internal monologue) must NOT be stored as content in the DB or included in any vault writeback. Instead:
- Store a raw artifact pointer: `{path, mtime, size, content_hash, format, extraction_status: "pointer_only"}`
- Extract only safe operational fields: task description, repository, commands run, files touched, decisions made, failures encountered, final outcome

### What to extract from Antigravity sessions

For each session directory or file:
- Task/goal (from first user message or task metadata if present)
- Repository or workspace path
- Commands run (shell commands, tool calls)
- Files touched (created, modified, deleted)
- Decisions made (explicit decision records or strong assertion patterns)
- Failures/errors encountered
- Final outcome / resolution status
- Session start/end timestamps (from file mtime if no metadata)

### Not to extract

- Raw reasoning traces
- Full message content (store pointer only unless content is clearly non-sensitive structured metadata)
- API keys, tokens, secrets (caught by Plan 13-06 redaction before any storage)

### Debug mode

`health_check()` returns:
- discovered source path count by format type
- session candidate count
- unknown binary file count and paths (without content)
- any read errors

## Standards

- Never mutate any Antigravity file.
- Unknown format files are always skipped safely — they never cause an exception that halts the sync.
- Reasoning trace content never reaches `upsert_session` data or any writeback candidate.
- The provider must be resilient to Antigravity schema changes: if a known key or field disappears, log and continue rather than failing the entire import.
