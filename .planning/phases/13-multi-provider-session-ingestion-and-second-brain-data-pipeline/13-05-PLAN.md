# Plan 13-05: Incremental Sync And CLI Commands

## Objective

Build the `aios sessions` CLI and the cron-friendly sync wrapper. Implement incremental cursoring so repeated runs only process new or changed sources. Ensure all sync modes are idempotent.

## Scope

### CLI: `bin/sessions.py`

Implement as a top-level CLI script callable as `python3 ~/AIOS/bin/sessions.py <subcommand>` (or via the existing `aios` CLI wrapper if one exists).

| Subcommand | Flags | Behavior |
|-----------|-------|----------|
| `sync` | `--provider <id>`, `--all`, `--dry-run` | Run incremental sync for one or all providers |
| `status` | — | Show last scan time, session count, and health for each provider |
| `backfill` | `--provider <id>`, `--all` | Full scan ignoring cursors; idempotent |
| `repair` | `--provider <id>` | Re-normalize sessions with missing/stale fields |
| `debug` | `--provider <id>` | Run provider.health_check(); print sources and counts; no content |

### Incremental cursor logic

On each sync for a provider:
1. Load `session_provider_cursors` rows for `provider_id`
2. Call `provider.discover_sources()` to get all candidate paths
3. For each path: compare current `mtime`, `size`, and `hash` against stored cursor
4. If changed (or no cursor): call `extract_raw_session` → `normalize_session` → `compute_fingerprint` → `upsert_session`
5. Update `session_provider_cursors` row with new values and `last_scanned_at = now()`

### Idempotency

`upsert_session` must use `stable_session_id` as the uniqueness key:
```sql
INSERT INTO session_imports (...) VALUES (...)
ON CONFLICT (stable_session_id) DO UPDATE SET updated_at = excluded.updated_at, ...
```
Backfill re-runs must produce the same DB state as a single run.

### Dry-run mode

No DB writes at any layer. Print a summary:
```
[dry-run] cursor: 3 sources found, 1 new, 2 unchanged
[dry-run] antigravity: 7 sources found, 7 new (backfill)
```

### Cron wrapper: `bin/cron-ingest-sessions.py`

- Calls `sessions.py sync --all`
- Appends structured log lines to `~/AIOS/logs/cron.log`
- Exit 0 on success; exit 1 on partial failure with logged error
- Does NOT replace or touch `cron-ingest-codex.py`

### Scheduler wiring

Document in Plan 13-08 docs. Suggested cron line:
```
0 * * * * python3 ~/AIOS/bin/cron-ingest-sessions.py >> ~/AIOS/logs/cron.log 2>&1
```

## Standards

- `--dry-run` must never write to DB, files, or logs (beyond stdout).
- Idempotency is a hard requirement: two consecutive runs with no source changes must produce identical DB state.
- `status` must not scan or process any sources — it only reads cursor and summary metadata.
