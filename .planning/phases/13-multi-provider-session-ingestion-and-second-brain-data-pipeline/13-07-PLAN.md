# Plan 13-07: Session Summarization And Writeback Proposals

## Objective

Implement structured session summarization and the writeback proposal layer. All four providers produce the same 16-field summary format. Writeback proposals are proposals only — no automatic vault mutation beyond what `auto_ingest.sh` already governs.

## Scope

### Session summarizer (`services/session_summarizer.py`)

`summarize_session(session_id, conn)` produces a `SessionSummary` with these 16 fields:

| Field | Type | Description |
|-------|------|-------------|
| `what_i_was_trying_to_do` | str | Primary goal, inferred from first user message or task metadata |
| `project_repo_involved` | str | Project name and repo path |
| `important_context_used` | list[str] | Key files, docs, truth references consumed |
| `decisions_made` | list[str] | Explicit decisions extracted from session |
| `files_modules_touched` | list[str] | Files created, modified, or deleted |
| `commands_tools_used` | list[str] | CLI commands and tool calls (redacted) |
| `bugs_failures_encountered` | list[str] | Errors and failure modes |
| `successful_fixes` | list[str] | Confirmed resolutions |
| `unresolved_follow_ups` | list[str] | TODOs, open questions, unresolved deltas |
| `reusable_patterns` | list[str] | Repeatable patterns worth extracting |
| `candidate_skills_to_extract` | list[str] | Specific skill/workflow candidates |
| `should_update_truth_file` | bool | True only if project state clearly changed |
| `should_create_obsidian_note` | bool | True if session is high-signal and safe to promote |
| `confidence` | float | 0.0–1.0; low confidence suppresses truth/writeback proposals |
| `source_provenance` | dict | provider, session_id, source_files, imported_at |
| `writeback_proposal_status` | str | pending / approved / rejected / held_redaction_incomplete |

### Writeback proposal emitter (`services/session_writeback.py`)

`emit_writeback_candidates(session_id, summary)`:
1. If `should_create_obsidian_note` is True and `confidence >= 0.6`:
   - Write `logs/summaries/<session_id>.json` with structured fields (no raw transcript)
   - Insert a `memory_writeback_proposals` row with `status = "pending"`
2. If `should_update_truth_file` is True and `confidence >= 0.8`:
   - Emit a separate truth update proposal with `type = "truth_update"`
3. Detect skillification candidates: query last 30 days for sessions with matching `reusable_patterns` across 3+ sessions; emit `type = "skillification_candidate"` proposal if threshold met

### What must never appear in a writeback candidate

- Raw message arrays or transcript content
- Reasoning traces
- Redacted secrets (even as `[REDACTED]` in bulk message dumps)
- More than a concise structured summary of each field

### Relationship to `auto_ingest.sh`

The existing `auto_ingest.sh` reads from `logs/summaries/*.json` and writes vault notes. Plan 13-07 produces the same JSON format that `auto_ingest.sh` already consumes. No changes to `auto_ingest.sh` are required — the new providers plug into the existing promotion flow.

## Standards

- `summarize_session` must call `redact_session` before inspecting any content.
- Sessions with `writeback_proposal_status = "held_redaction_incomplete"` never produce vault notes.
- Confidence scoring is conservative: missing key fields reduce confidence; short sessions default to low confidence.
