# Plan 16-01: Existing AIOS Harness Audit And Source-Of-Truth Map

## Objective

Audit the current AIOS harness before implementation. The output is the required audit report from the source spec, with enough concrete file/component mapping that Plans 16-02 through 16-06 can patch specific seams instead of re-discovering the system.

## Scope

Create `docs/audits/aios-harness-determinism-audit.md`.

The audit must inspect current repo state and map:

- harness entrypoints
- orchestration logic
- agent/task lifecycle
- task state representation
- prompt/template system
- model-selection logic
- second-brain integration
- benchmark/evaluation system
- verification/testing flow
- evidence/logging artifacts
- session recovery behavior
- shadow-branch workflow
- memory or retrospective system
- docs and operator instructions
- scripts and CI checks
- known experimental branches or WIP areas

## Required Audit Sections

1. Existing AIOS architecture summary
2. Current source-of-truth map
3. Lifecycle phase comparison table
4. What already overlaps with Case
5. Top 5 gaps
6. Top 5 risks if unchanged
7. Proposed targeted deltas
8. Files likely to edit
9. Files that should not be touched
10. Changes explicitly rejected as too invasive
11. Implementation plan ordered by leverage

## Standards

- Read before proposing changes. Do not infer from file names alone.
- Cite concrete files and functions where possible.
- Prefer "patch existing component X" over "create new framework Y".
- Mark unknowns honestly when a surface cannot be verified from current code.

## Verification

- `docs/audits/aios-harness-determinism-audit.md` exists and contains every required section.
- The audit cites actual AIOS files for each major harness area.
- The audit has enough specificity to drive the rest of Phase 16 without another broad discovery pass.
