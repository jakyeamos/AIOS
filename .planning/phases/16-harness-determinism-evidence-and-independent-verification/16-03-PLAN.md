# Plan 16-03: Independent Verifier Gate

## Objective

Make verification structurally independent from implementation. AIOS should require a verifier artifact for implementation-bearing governed workflows, and that verifier must inspect task spec, changed files or diff, and evidence artifacts rather than trusting the implementer summary.

## Scope

Add the minimal verifier artifact and closeout gate needed by the current workflow system.

Implementation should prefer:

- additive persistence in `schema.sql`
- `services/verifier_artifacts.py` for schema and validation helpers
- closeout integration through the seam identified in Plan 16-01
- workflow registry/config flags only where needed to identify implementation-bearing workflows and exemptions
- CLI inspection through `services/aios_cli.py`

## Verifier Artifact Shape

Required fields:

- `task_id`
- `run_id`
- `verifier_agent`
- `model`
- `inputs_reviewed_json`
- `checks_performed_json`
- `result`: `pass | fail | needs_work`
- `blocking_issues_json`
- `non_blocking_issues_json`
- `recommended_next_phase`: `closeout | implementation_retry | human_review`
- `evidence_refs_json`

## Standards

- Do not spawn a verifier automatically unless the existing harness already has an appropriate mechanism. This plan can add the artifact contract and closeout gate first.
- Verification-exempt workflows must be explicit and auditable.
- A verifier artifact without evidence references is invalid for implementation-bearing work.
- Closeout must surface why verification blocked completion.

## Verification

- Tests prove missing verifier artifact blocks completion where required.
- Tests prove `fail` and `needs_work` do not route to closeout.
- Tests prove verifier artifacts must cite evidence refs or concrete files for blocking issues.
