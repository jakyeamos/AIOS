# Plan 16-05: Deterministic Phase Gates And Prompt Boundary Tightening

## Objective

Reduce reliance on prose instructions for critical workflow transitions. Where AIOS currently asks agents to remember phase boundaries, evidence requirements, or verification rules, move the minimal safe subset into config or deterministic code.

## Scope

Start with an audit document, then make the smallest implementation patch.

Audit:

- duplicated instructions
- bloated prompts
- stale rules
- unclear phase boundaries
- missing output schemas
- prompts doing work that should be deterministic code
- missing distinction between orchestrator, implementer, verifier, reviewer, and retrospective prompts

Implementation targets:

- workflow stage metadata for evidence and verifier requirements
- loader normalization in `services/workflow_orchestration.py`
- CLI/audit visibility in `services/aios_cli.py`
- targeted prompt/template updates only where needed

## Standards

- Do not rewrite all prompts.
- Do not replace existing workflow orchestration.
- Prefer config and small loader changes over a new state-machine framework.
- Keep backward compatibility for existing workflow registry entries through safe defaults.

## Verification

- Tests cover workflow loader defaults for old entries.
- Tests cover at least one workflow/stage with deterministic evidence or verifier gate metadata.
- CLI or audit output shows gate requirements without reading prompt prose.
