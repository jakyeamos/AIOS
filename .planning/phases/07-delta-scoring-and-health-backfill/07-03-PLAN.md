<objective>
Project the Python delta-explanation and workflow-from-health contracts (from plan 07-02) onto the UI layer and add three CLI subcommands so operators can drive DELT-02 drill-downs and DELT-04 recommendations from the command line.

Purpose: DELT-02 acceptance requires drill-downable explanations on operator surfaces (per TIER_ONE_ACCEPTANCE_CHECKLIST Phase 7 "No score may appear without a drill-down path"). DELT-04 acceptance requires a usable recommendation surface that does not silently launch unregistered workflows (Pitfall 3) and surfaces the approval requirement upfront (Pitfall 6). And the new domain evaluators from plan 07-01 stay `unknown` forever unless an operator can flip them via `aios standards-override` (Pitfall 5).

Output: extended TypeScript types in `aios-ui/lib/control-plane.ts`, two new read-time projection functions in `aios-ui/server/aios/standards-health.ts` plus integration into `getProjectStandardsHealth`, three new `aios` CLI subcommands (`delta-explain`, `recommend-workflow`, `standards-override`), an extended `governance-audit` JSON output with a `recommended_workflows` block, and CLI tests covering each.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI operator -> `standards_manual_overrides` | The `standards-override` command writes operator-supplied status + actor + rationale into a durable table. | `standards_manual_overrides` -> `evaluate_and_record` | The override merge happens at evaluation time. Caller-provided `overrides=` kwarg wins over table values so test fixtures and programmatic flows are not silently overridden by stale rows. |

| `aios-ui` deltaExplanations + recommendedWorkflows -> operator UI | These projections expose remediation guidance and workflow recommendations to operator surfaces. The data is already in `standards_assessments` and `standards_delta_items`; the projection does not introduce new disclosure. |
