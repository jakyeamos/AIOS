# Plan 17-03: Capability Assets And Routing Metadata

## Objective

Implement the DX pack's capability assets and routing metadata inside AIOS's existing registries and loaders.

## Scope

Use the integration point selected by Plan 17-01. Likely targets include:

- `config/workflows/registry.json`
- `config/workflows/skills.json`
- `prompts/registry.json`
- `services/workflow_orchestration.py`
- `services/aios_cli.py`

Do not create standalone `agents/*.md` or `commands/*.md` files unless the audit proves those are the repo convention.

## Routing Triggers

Implement metadata for:

- DX optimizer: slow or unclear setup, workflow improvement requests, missing validation commands, repeated tooling friction, onboarding or peer-run setup.
- Interface reviewer: public API, CLI, SDK, config schema, developer-facing error messages.
- Docs writer: missing/stale README, setup flow changes, command changes, public API/CLI changes, handoff requests.
- Security reviewer: auth, secrets, permissions, shell, network, CI, MCP, filesystem writes, automation, dependencies.
- TypeScript specialist: public TypeScript APIs, strict type errors, package boundaries, monorepo build/typecheck, inference quality.
- Spec-fidelity coder: PRD, ADR, implementation spec, issue, acceptance criteria.

## Verification

- Registry/load tests pass.
- DX capabilities can be listed or inspected through existing CLI/audit command or a new narrow command.
- No fixed model is encoded per capability.
