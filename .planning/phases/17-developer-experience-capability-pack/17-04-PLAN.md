# Plan 17-04: Dynamic Mode And Model Routing

## Objective

Add dynamic mode and model/reasoning routing for DX capabilities. The pack should use compact review for small tasks, full audit for broad DX work, implementation mode when asked to change files, and targeted specialist review only when justified.

## Scope

Extend existing routing and execution strategy surfaces. If Plan 17-01 identifies a better home than the listed files, use that home.

## Reasoning Levels

Define metadata for:

- `low`: docs cleanup, simple README improvements, small config changes
- `medium`: DX audits, TypeScript refactors, interface reviews, test additions
- `high`: architecture-affecting changes, security-sensitive automation, ambiguous multi-file implementation, model-routing or agent-runtime changes

## Escalation Triggers

Include:

- conflicting requirements
- security-sensitive change
- destructive operation
- repeated test failure
- unclear architecture boundary
- high token/tool cost without progress
- public API compatibility risk

## Verification

- Tests prove simple docs cleanup does not escalate to high reasoning.
- Tests prove security-sensitive automation triggers higher reasoning or human gate metadata.
- Tests prove TypeScript specialist is not invoked for simple non-TypeScript work.
