# Plan 17-05: Developer Experience Eval Hooks And Fixtures

## Objective

Make the DX pack measurable. Add eval coverage that proves the pack routes correctly, avoids checklist bloat, measures or marks metrics honestly, and works with and without second-brain context.

## Scope

Add a human-readable eval spec and, where compatible with current infrastructure, machine-readable fixtures.

Required scenarios:

1. Poor onboarding repo
2. Public CLI change
3. TypeScript package boundary change

## Evaluation Criteria

The eval should test whether AIOS:

- detects missing setup instructions
- detects missing validation commands
- measures or identifies dev-loop bottlenecks
- produces a priority matrix with impact and effort
- improves README clarity without marketing fluff
- reviews a CLI/API from the consumer perspective
- performs contextual security review
- invokes TypeScript specialist only when justified
- routes spec-to-code tasks to implementation mode
- logs assumptions instead of blocking unnecessarily
- works with second-brain context available
- works without second-brain context
- produces small, reviewable changes
- records before/after metrics when possible

## Verification

- Eval spec exists and covers all criteria.
- Fixtures are parseable if machine-readable fixtures are added.
- Existing harness eval tests pass or are updated with focused coverage.
