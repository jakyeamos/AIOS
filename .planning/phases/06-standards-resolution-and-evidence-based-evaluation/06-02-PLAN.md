<objective>
Add stage-level criterion evaluation so workflow validation produces structured findings instead of free-form `issues[]` lists, and persist those findings durably for governance and phase 7 delta scoring.

Purpose: deliver STND-02 (evaluate outputs against explicit quality criteria rather than generic model judgment) at stage granularity and STND-04 (preserve durable evaluation findings) by extending the existing run-level evaluator pattern down to the stage boundary, without inventing a new framework.

Output: a new `success_criteria_stage_findings` SQLite table, `evaluate_stage_findings()` and `persist_stage_findings()` helpers in `services/success_criteria.py`, a post-stage evaluation hook inside `services/workflow_orchestration.py:execute_workflow`, an aggregated `stage_evaluations` block in the governed closeout report emitted by `bin/hook-stop.py`, and unit + integration tests proving stage findings round-trip from execution through closeout.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stage evaluator handlers -> finding rows | Evaluator handlers are existing in-tree functions; no new external evaluator surface is added. |
| Workflow stage outcome -> governance.requires_review | A blocker-level stage finding must flip `requires_review = True` so phase 5's governance audit picks it up. |
| Stage findings table -> phase 7 delta scoring | Findings must be queryable by (run_id, stage_key, criterion_id, level). Indexes enforce the query shape. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Tampering | success_criteria_stage_findings | mitigate | Findings are written only by `persist_stage_findings()`, which is called from `execute_workflow` and (later) from hook-stop. No external write surface; criterion_id is validated against the registry before persistence. |
| T-06-06 | Repudiation | stage_status calculation | mitigate | `stage_status` is derived from `blocker_count > 0` and persisted alongside the findings; the workflow_execution_report captures the stage_evaluations aggregate so the verdict cannot be silently reclassified later. |
| T-06-07 | Information Disclosure | JSON artifact write path | accept | The `data/success-criteria/evaluations/` directory is internal; no operator-uploaded content reaches the artifact write. |
| T-06-08 | Elevation of Privilege | Blocker promotion rule | mitigate | Stage-level blocker promotion reuses the run-level `criterion.blocking == True` rule (see Anti-Pattern: Implicit blocker promotion in RESEARCH.md). No new promotion policy is invented at stage level. |
</threat_model>
