<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Registry JSON -> Python loader | `config/success-criteria/registry.json` and `config/standards/registry.json` are parsed via `_load_json` with type guards; untrusted edits could attempt to inject criterion ids that don't have evaluators. |
| project_standards_profiles row -> resolution result | A missing row must surface `no_profile_attached` rather than silently returning an empty standards list (Pitfall 3). |
| briefing_packets persisted resolution -> closeout consumer | Resolution drift between session-start preview and session-close evaluation must be avoided (Pitfall 1). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | resolve_task_standards / briefing_packets | mitigate | Resolution is computed once at session-start and persisted; closeout reads the persisted JSON columns. Any mismatch between persisted and re-derived results is logged but does not silently overwrite the persisted value. |
| T-06-02 | Repudiation | project_standards_profiles missing row | mitigate | `resolve_task_standards()` returns `resolution_status = "no_profile_attached"`; downstream surfaces (hook-session-start, agentize) must propagate this status into the packet rather than silently emitting an empty list. |
| T-06-03 | Information Disclosure | standards registry parse | accept | The registry is internal config and not exposed to operator input; `_load_json` already type-guards values. |
| T-06-04 | Elevation of Privilege | applicability filter | mitigate | `_standard_applies` defaults to True only when `standard.applicability` is empty (intentional opt-in default); explicit non-matching patterns exclude the standard. No wildcard escalation path is added. |
</threat_model>
