# Plan 12-05: Memory Packet Contract

## Objective

Write `docs/specs/memory-packet-contract.md`, the formal specification governing what every model-facing memory packet must contain, how it is structured, and what rules the compiler must enforce.

## Scope

- Define required and optional sections
- Define section ordering
- Define JSON/schema representation for internal use
- Define model-facing markdown format
- Define provenance, staleness, contradiction, confidence, and token-budget rules
- Provide good and bad packet examples

## Output

Write `docs/specs/memory-packet-contract.md`. This document is the authoritative contract that `services/memory_compiler.py` (Plan 12-03) must conform to and that `tests/` (Plan 12-06) must validate.

## Implementation Notes

- The contract is written before the compiler implementation (Plan 12-03 depends on this plan being complete in wave 2).
- Good/bad examples should use realistic AIOS memory content, not generic Lorem Ipsum.
- The immutable rule — raw JSON may not appear in model-facing output — must be stated explicitly as a hard constraint, not a recommendation.
