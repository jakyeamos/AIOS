# Plan 12-07: Memory Backfill Plan

## Objective

Write `docs/backfills/graph-native-memory-backfill.md`, a prioritized inventory of existing AIOS memory hotspots and the structured facts and relationships that should be extracted from them into Layers B and C.

## Scope

- Inspect existing project truth files, PRDs, agent rules, user preferences, long-term memory notes, decision logs, code quality rules, prompt libraries, design specs, and wiki pages
- For each hotspot: document current value, missing structure, recommended fact extraction, recommended relationships, stable vs dynamic classification, project vs global scope, and P0/P1/P2 priority
- P0 entries must trace to audit findings from Plan 12-01

## Output

Write `docs/backfills/graph-native-memory-backfill.md`. This document is an execution guide for a future backfill run, not a design spec. It should be concrete enough that an agent can pick up any P0 entry and know exactly what Layer B rows and Layer C edges to create.

## Implementation Notes

- This plan does not perform the actual backfill. It writes the plan document only.
- The backfill document will inform future quick tasks or a Phase 13 backfill execution phase.
- Priority assignment: P0 = memory is actively lost today without this backfill; P1 = retrieval quality is measurably weaker without it; P2 = nice to have.
