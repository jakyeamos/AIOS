# Plan 12-08: KV-Cache-Aware Local Runner Future Design Note

## Objective

Write `docs/future/kv-cache-aware-local-runner.md`, a design note explaining why direct KV-cache injection is not a core AIOS dependency today and what prerequisites would need to be true before it becomes one.

## Scope

- Explain why direct KV-cache injection is not practical for closed API models
- Explain what local/open-source model runners (vLLM, LMCache) would need to expose
- Define prerequisites for AIOS to depend on it
- Explain how the stable-prefix ContextCompiler (Plan 12-04) bridges today and that future
- State the position clearly: KV-cache-level memory is an optimization layer, not the source of truth

## Output

Write `docs/future/kv-cache-aware-local-runner.md`. This is a pure design note — no code, no schema, no dependencies introduced.

## Implementation Notes

- The key position must be stated early and unambiguously: AIOS must not make KV-cache injection a hard dependency.
- The document should be useful to a future engineer or AI deciding whether to add a local model runner. It should make the tradeoffs clear, not just discourage the idea.
- Keep the note concise — 500–800 words is the target. This is not an RFC.
