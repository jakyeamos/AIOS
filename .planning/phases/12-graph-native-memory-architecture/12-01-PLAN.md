# Plan 12-01: Memory Architecture Audit

## Objective

Inspect the entire AIOS repository and produce a written audit of the current memory, retrieval, context-packing, and agent-briefing architecture. This audit is the input contract for all subsequent Phase 12 plans.

## Scope

Inspect the following systems and produce concrete findings for each:

- Raw memory storage (notes, transcripts, repo events, agent outputs, design decisions, uploaded files, external research)
- File and document ingestion
- Note and context indexing
- Semantic search
- Keyword/grep search
- Project-specific context retrieval
- Agent prompt construction
- Context packet generation
- User preference retrieval
- Long-term memory updates
- Conflict and staleness handling
- Source and provenance tracking
- Prompt caching or stable-prefix prompting
- Any existing graph, entity, relationship, or metadata storage

## Output

Write `docs/audits/graph-native-memory-audit.md` with sections:
1. Current Architecture Summary (with file paths and module names)
2. Strengths
3. Weaknesses
4. Memory Loss Hotspots
5. Flat Retrieval / Semantic-Search-Only Areas
6. Raw Structured Data That Is Hard for Models to Use
7. Missing Provenance, Staleness, and Conflict Handling
8. Prompt Caching Opportunities
9. Implementation Recommendations (ranked by impact × effort)

## Standards

- Every finding must reference an actual file or module.
- Recommendations must be concrete enough that a subsequent plan can implement one without re-deriving the problem.
- Do not propose solutions in this plan — describe the current state accurately.
