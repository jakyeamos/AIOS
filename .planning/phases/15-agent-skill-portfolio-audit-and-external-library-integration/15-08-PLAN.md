# Plan 15-08: Add Handoff Skill With AIOS Session Integration

## Objective

Create a `handoff` skill that produces compact, focus-tailored cross-session continuation documents and writes them to the AIOS DB, enabling future sessions to pick up exactly where the current one ended.

## The Core Purpose Of A Handoff

A handoff is not a progress summary. It is a cold-start brief — the minimum context a new agent needs to begin the right next action without asking clarifying questions. It assumes the next session has access to the codebase and AIOS context; it does not re-explain what already exists.

## Seven Behaviors

### 1. Compact And Focus-Tailored
Write for the next session's intended focus, not for a general audience. If the next session will implement Plan 15-05, the handoff says: "Implementing Plan 15-05. The issues_store schema is agreed. Start with the `issues_store.py` service file, then wire it into the skill." It does not re-summarize the entire Phase 15 history.

### 2. Save Outside The Current Workspace
Default storage: a user-level AIOS handoffs directory outside the current project workspace.

Also write a record to `aios.db` via `handoff_store.py`. The markdown file is the readable artifact; the DB record is the index.

### 3. Suggest Skills For The Next Session
Recommend 2–4 skills the next session should load immediately, with one-sentence rationale for each:

```markdown
## Suggested Skills For Next Session
- `to-issues` — open issues for Phase 15 plans 05 and 08 are in aios.db; use this skill to list or update them
- `diagnose` — the session_ingestion pipeline has a flaky test that will likely need debugging
```

### 4. Reference Don't Duplicate
- PRDs and plans: reference the relevant plan or PRD path directly.
- Open issues: `See aios.db issues table for project=AIOS, status=open`
- Commits: `See commit abc1234 — "add issues_store service"`
- ADRs: reference the relevant ADR path directly.

Do not copy the content of these documents into the handoff.

### 5. Redact Secrets
Scan the handoff for patterns matching: API keys, tokens, passwords, connection strings, private keys, personal identifiers. Replace with `[REDACTED: <description of what was here>]`. Flag the redaction count in the handoff header.

### 6. Start Here Section
Every handoff must begin with:

```markdown
## Start Here
[One paragraph. The single most important next action, stated concretely enough to begin without additional context.]
```

### 7. Intended Focus
Every handoff must declare its intended scope:

```markdown
## Intended Focus For Next Session
[2–3 sentences. What problem space, which files, which plan or feature. What is out of scope for this handoff.]
```

## Handoff Store Service

Create `services/handoff_store.py`:

```python
"""
Handoff store: persist cross-session handoff records in aios.db.
Created by Phase 15 to support the handoff skill.
"""

import sqlite3
from pathlib import Path

AIOS_DB = Path.home() / "AIOS" / "data" / "aios.db"
HANDOFFS_DDL = """
CREATE TABLE IF NOT EXISTS handoffs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT,
    project TEXT NOT NULL,
    focus TEXT,
    suggested_skills TEXT,   -- JSON array of skill names
    source_run_id TEXT,
    content_path TEXT,       -- path to the .md handoff file
    redacted INTEGER DEFAULT 0 CHECK(redacted IN (0, 1)),
    created_at TEXT DEFAULT (datetime('now'))
)
"""

def _conn():
    conn = sqlite3.connect(AIOS_DB)
    conn.execute(HANDOFFS_DDL)
    conn.commit()
    return conn

def write_handoff(session_id, project, focus, suggested_skills=None,
                  source_run_id=None, content_path=None, redacted=False):
    import json
    with _conn() as conn:
        conn.execute(
            "INSERT INTO handoffs (session_id, project, focus, suggested_skills, source_run_id, content_path, redacted) VALUES (?,?,?,?,?,?,?)",
            (session_id, project, focus, json.dumps(suggested_skills or []),
             source_run_id, str(content_path) if content_path else None, int(redacted))
        )

def list_handoffs(project=None, limit=10):
    with _conn() as conn:
        if project:
            return conn.execute(
                "SELECT * FROM handoffs WHERE project=? ORDER BY id DESC LIMIT ?",
                (project, limit)
            ).fetchall()
        return conn.execute(
            "SELECT * FROM handoffs ORDER BY id DESC LIMIT ?", (limit,)
        ).fetchall()
```

## Handoff Markdown Template

```markdown
# Handoff: <project> — <slug>

**Session:** <session-id>
**Date:** <YYYY-MM-DD HH:MM>
**Redactions:** <count>

## Start Here
[Most important next action]

## Intended Focus For Next Session
[Scope and out-of-scope]

## State At Close
[What was completed, what was left open — in bullets, not prose]

## Open Issues
[References to aios.db or issue files — do not copy content]

## Key Decisions Made
[Only decisions not recorded in ADRs or commit messages]

## Suggested Skills For Next Session
- `skill-name` — rationale

## Files To Read First
[2–5 most relevant files for the next session's focus]
```

## Standards

- The markdown fallback to a user-level AIOS handoffs directory must work without AIOS installed.
- The skill must not write anything to the current workspace by default; handoffs belong outside the project directory unless the user explicitly requests otherwise.
- Depends on Plan 15-05 because the handoff skill references open issues from the issues store.
