# Plan 15-05: Add To-Issues Skill With AIOS Run Integration

## Objective

Create a `to-issues` skill that decomposes plans, PRDs, and design specs into independently-grabbable implementation issues using vertical tracer-bullet slices. Issues are stored in `aios.db` via a new `issues_store` service, with optional GitHub CLI publication and a markdown fallback.

## Skill Behavior

### Vertical Tracer-Bullet Slices

The fundamental decomposition unit is a vertical slice: one thin strip of behavior from input to output, touching all relevant layers (UI → API → DB, or prompt → service → store). A good issue is NOT:

- "Implement the database schema for users"
- "Write the API endpoints for authentication"
- "Build the login form"

A good issue IS:

- "User can log in with email and password — form submits, API validates, DB stores session, redirect on success"

Each slice should be demoable or verifiable by a single tester or CI run without requiring other unfinished issues.

### AFK vs HITL Labels

Every issue gets one of:

- **AFK** — an agent can implement this without human input during execution; acceptance criteria are unambiguous and mechanically verifiable
- **HITL** — a human must review a decision, approve a UX choice, or provide information the agent cannot determine from the codebase

Include a one-sentence rationale for the label.

### Dependencies And Blockers

List other issues (by title or ID) that must be complete before this issue can start. A good decomposition minimizes the dependency chain depth; flag chains longer than three issues as a decomposition risk.

### Acceptance Criteria And Test Expectations

Each issue must include:
- 2–5 acceptance criteria written as observable behaviors ("given X, when Y, then Z")
- At least one test expectation naming the test type and what it verifies

## AIOS Integration

When the AIOS environment is available (check for `services/issues_store.py`), call it to persist issues:

```python
from services.issues_store import write_issue
write_issue(
    title=...,
    description=...,
    acceptance_criteria=...,
    afk_hitl="AFK" | "HITL",
    dependencies=[...],
    linked_run_id=run_id,  # from current AIOS session context if available
    source_file=...,       # path to the PRD/plan being decomposed

```

If `issues_store.py` is not available or `aios.db` is unreachable, fall back to writing a markdown file per issue under a user-level AIOS issues directory.

## issues_store Service

Create `services/issues_store.py`:

```python
"""
Issues store: write and list implementation issues in aios.db.
Created by Phase 15 to support the to-issues skill.
"""

import sqlite3
from datetime import datetime
from pathlib import Path

AIOS_DB = Path.home() / "AIOS" / "data" / "aios.db"
ISSUES_DDL = """
CREATE TABLE IF NOT EXISTS issues (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project TEXT NOT NULL,
    title TEXT NOT NULL,
    description TEXT,
    acceptance_criteria TEXT,
    afk_hitl TEXT CHECK(afk_hitl IN ('AFK', 'HITL')),
    dependencies TEXT,      -- JSON array of issue titles/IDs
    linked_run_id TEXT,
    source_file TEXT,
    status TEXT DEFAULT 'open' CHECK(status IN ('open', 'in_progress', 'done', 'cancelled')),
    created_at TEXT DEFAULT (datetime('now'))
)
"""

def _conn():
    conn = sqlite3.connect(AIOS_DB)
    conn.execute(ISSUES_DDL)
    conn.commit()
    return conn

def write_issue(title, description, acceptance_criteria, afk_hitl,
                dependencies=None, linked_run_id=None, source_file=None, project="unknown"):
    import json
    with _conn() as conn:
        conn.execute(
            "INSERT INTO issues (project, title, description, acceptance_criteria, afk_hitl, dependencies, linked_run_id, source_file) VALUES (?,?,?,?,?,?,?,?)",
            (project, title, description, acceptance_criteria, afk_hitl,
             json.dumps(dependencies or []), linked_run_id, source_file)
        )

def list_issues(project=None):
    with _conn() as conn:
        if project:
            return conn.execute("SELECT * FROM issues WHERE project=? ORDER BY id", (project,)).fetchall()
        return conn.execute("SELECT * FROM issues ORDER BY project, id").fetchall()
```

## Optional GitHub CLI Path

If `gh auth status` succeeds and the user opts in:

```bash
gh issue create --title "..." --body "..." --label "AFK" 
```

This is opt-in only. The default is always local storage.

## Standards

- The markdown fallback path must work even if AIOS is not installed at all.
- The `issues_store.py` migration must be idempotent (`CREATE TABLE IF NOT EXISTS`).
- The skill description must trigger on: "break this into issues", "turn this PRD into tasks", "make this plan into tickets", "decompose this", "what issues should we create".
