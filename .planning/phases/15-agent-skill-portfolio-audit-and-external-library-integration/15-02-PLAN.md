# Plan 15-02: Upgrade Interrogate Skill With Grill-With-Docs Behaviors

## Objective

Create the local `interrogate` skill at `../.claude/skills/interrogate/SKILL.md` (no global equivalent existed in the Plan 15-01 inventory) to incorporate the six key behaviors from `grill-with-docs` while preserving the existing one-at-a-time questioning discipline and Terrace/PRD preference.

## Behaviors To Add

### 1. Search Before Asking
Before posing a clarifying question, search the codebase. If the answer is in a file, read it and state what was found rather than asking. Questions are reserved for genuine ambiguity that code cannot resolve.

### 2. Challenge Against Repo Language
When the user proposes a design or plan, compare the terms used against existing names in the codebase (functions, types, modules, routes, DB columns). Flag mismatches. If the user calls something a "widget" and the codebase calls it a "component," resolve the terminology before proceeding.

### 3. Domain Glossary Maintenance
When a new canonical term is introduced or a fuzzy term is sharpened into a precise one, add or update the relevant project or planning context glossary. Create a context file if no suitable one exists.

### 4. ADRs Only For Durable Decisions
An ADR is appropriate only when a decision is: architectural (not tactical), likely to be revisited and questioned later, and not easily reversible. Do not create ADRs for implementation choices, style decisions, or anything that will be obvious from the code.

### 5. Canonical Language Sharpening
When the user's request contains fuzzy terms ("make it better", "clean this up", "handle errors properly"), ask one focused clarifying question to convert the fuzzy term into a measurable constraint before doing any work.

### 6. Cross-Check User Claims
When a user states that "X works this way" or "Y is already implemented," verify the claim by reading the relevant code before accepting it as a constraint. Surface discrepancies without judgment: "I checked — the current behavior is Z, not Y. Does the plan change?"

## Existing Behavior To Preserve

- Ask one clarifying question at a time; do not front-load multiple questions.
- Resolve ambiguity before implementation begins, not during.
- Trust the user's stated goals; challenge the assumptions and terminology, not the intent.
