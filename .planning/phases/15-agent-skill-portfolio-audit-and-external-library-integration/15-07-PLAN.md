# Plan 15-07: Consolidate Write-A-Skill Into One Canonical Authoring Workflow

## Objective

Produce a comparison matrix of all local skill-authoring skills, then consolidate them into a single canonical `write-a-skill` skill that incorporates the best of each plus the valuable parts of mattpocock's upstream skill.

## Step 1: Build The Comparison Matrix

Read the Plan 15-01 inventory and identify all skills related to skill authoring. For each, write a row in `docs/phase-15-skill-authoring-comparison.md`:

| Field | Description |
|-------|-------------|
| Skill path | Full path to the skill file |
| Strengths | What this skill does well that the others don't |
| Missing pieces | What mattpocock/write-a-skill has that this skill lacks |
| Overlapping pieces | Concepts or instructions duplicated across skills |
| Recommended merge target | Which skill should be the primary or whether to start fresh |

## Step 2: Write The Canonical Skill

The canonical `write-a-skill` skill must embody six principles:

### Principle 1: Concise SKILL.md Frontmatter

Every skill starts with:
```yaml
---
name: skill-name
description: [trigger-rich — see Principle 2]
---
```

The frontmatter is the primary triggering mechanism. It must be accurate and specific.

### Principle 2: Trigger-Rich Description Discipline

The description answers: "When would an agent load this skill without being explicitly asked?" Name:
- The user phrases that should trigger it
- The contexts and task types where it applies
- Edge cases where it applies even if the user doesn't use the skill's name

Bad description: "How to create a new skill."
Good description: "How to create, structure, and improve Claude Code skills. Use this skill whenever someone asks to create a skill, capture a workflow as a skill, improve an existing skill, write a SKILL.md, or turn a repeated process into a reusable agent behavior — even if they don't use the word 'skill.'"

### Principle 3: Progressive Disclosure

The SKILL.md body should be readable in under 5 minutes. If instructions are detailed:
- Main SKILL.md covers: what this skill does, when to use it, core workflow
- `references/` sub-files cover: detailed checklists, schemas, decision trees
- Reference files are cited from SKILL.md with "read `references/foo.md` when you need X"

### Principle 4: Reference Files For Long Instructions

When any section would exceed ~100 lines, extract it into `references/<topic>.md`. The main SKILL.md points to it. Future readers get progressive depth rather than a wall of text.

### Principle 5: Scripts For Deterministic Operations

When a skill involves a repeatable mechanical operation (formatting output, generating scaffolding, running a validation), write it as a script in `scripts/`. The skill calls the script rather than re-deriving the steps every time. Scripts are faster, more consistent, and easier to test than prose instructions.

### Principle 6: Examples Only When They Help

Add an example when:
- The expected output format is non-obvious from prose alone
- There is a common wrong version that examples help distinguish from the right version
- The example is short enough to read in context (< 20 lines)

Do not add examples for skills where the behavior is clear from the prose and names alone.

## Step 3: Deprecation Or Retirement Of Merged Skills

For any existing skill-authoring skill that is fully superseded by the canonical version:
- Add a header comment: "Superseded by ~/.claude/skills/write-a-skill.md — kept for reference"
- Do not delete (per Phase 15 safety rules)
- Note the retirement in `docs/phase-15-skill-authoring-comparison.md`

## Standards

- This plan requires user review (autonomous: false) because the comparison matrix involves a judgment call about which existing behaviors to keep, which to retire, and what the canonical skill's voice should be.
- Present the comparison matrix to the user before writing the canonical skill file.
- The canonical skill must itself be a good example of the principles it teaches — written with progressive disclosure, trigger-rich description, and concise structure.
