# Plan 23-02: Class-Based Strict Readiness Contract

## Objective

Define the exact gate standard for each repo class so later plans can mature repos without inventing requirements.

## Scope

- Document required gates for:
  - platform/control-plane
  - production/public web apps
  - developer tools/packages
  - Python/data/research/course repos
  - content/vault/container repos
- Define accepted non-remote CI exception format: owner, reason, review date, local proof command, and replacement path.
- Define what evidence must be recorded before removing `floor_only` or `pre_cr_only`.
- Add class/applicability metadata to AIOS quality pipeline config where needed.

## Verification

- Standards contract exists and cites Phase 23 audit.
- Quality pipeline config can represent every repo class.
- Focused quality-gate config validation passes.
