# Plan 18-01: Meta-Learning Architecture Audit

## Objective

Audit AIOS's current learning, session, rule, skill, command, agent, proposal, and permission surfaces before implementing the meta-learning layer.

## Scope

Create `docs/audits/aios-meta-learning-audit.md`.

The audit must include:

- Current-state summary
- Gaps
- Recommended architecture
- Files to modify
- Risks
- Implementation plan
- Test plan

## Questions To Answer

1. Where should AIOS store learned workflow rules?
2. Where should AIOS store project-specific conventions?
3. Where should AIOS store reusable skills?
4. Where should AIOS store command suggestions?
5. Where should AIOS store agent/sub-agent suggestions?
6. Where should AIOS store things that should not become rules yet but may be useful later?
7. How can learned changes be tested on shadow branches before promotion?
8. What parts of the repo should never be automatically modified?
9. What safety checks are needed before allowing any auto-permission recommendation?
10. What minimal implementation can produce immediate value without overengineering?

## Verification

- Audit file exists and answers all ten questions.
- Audit cites concrete AIOS files/components.
- Audit identifies a minimal v1 path and explicitly rejects silent mutation.
