# Plan 18-03: Confidence Scoring, Quality Filter, And Target-Layer Router

## Objective

Score extracted signals, filter out low-quality learnings, detect conflicts, and route accepted signals to the correct AIOS layer.

## Scope

Create focused scoring and routing modules. Keep policy values explicit in code or a small config file; avoid a large framework.

## Scoring Policy

Implement defaults:

- Explicit always/never/from-now-on correction: +5
- Repeated correction across 2+ sessions: +4
- Repeated correction within one session: +3
- Single correction: +2
- Repeated approval: +2
- Single approval: +1
- Repeated manual command: +3
- Repeated tool loop/failure: +3
- Repeated model mismatch: +3
- Repeated context miss: +4

Modifiers:

- Recent signal: +1
- User explicitly asked to remember it: +2
- Evidence from multiple projects: +2
- Contradiction: conflict, no auto-promotion
- High blast radius, security-sensitive, permission/auto-allow: manual review required

## Verification

- Tests cover scoring bands.
- Tests cover the quality filter.
- Tests cover project vs global routing.
- Tests cover skill vs command routing.
- Tests cover contradiction handling.
