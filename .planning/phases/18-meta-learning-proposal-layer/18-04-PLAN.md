# Plan 18-04: Proposal Generator And Review Lifecycle

## Objective

Turn routed signals into reviewable proposals that can be accepted, rejected, shadow-tested, or left observed without mutating behavior automatically.

## Scope

Implement proposal generation and minimal persistence.

Prefer:

- JSONL or Markdown files for v1, or
- existing AIOS writeback/proposal tables if Plan 18-01 proves that path is cleaner.

## Proposal Fields

Required:

- `proposal_id`
- `title`
- `summary`
- `target_layer`
- `target_file`
- `confidence_score`
- `risk_level`
- `evidence`
- `why_this_layer`
- `proposed_patch`
- `rollback`
- `requires_manual_approval`

## Verification

- Tests cover proposal formatting.
- Tests cover stable proposal IDs.
- Tests prove proposals default to manual approval.
- Tests cover conflict proposal formatting.
