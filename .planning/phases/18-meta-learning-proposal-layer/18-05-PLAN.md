# Plan 18-05: Auto-Allow Safety Gate

## Objective

Prevent frequency-based permission creep. AIOS may notice repeated commands, but auto-allow recommendations must be risk-scored and separated from ordinary learning proposals.

## Scope

Create a small auto-allow safety module and policy doc.

## Recommendation Categories

Safe to suggest:

- Read-only commands
- Deterministic local inspection
- Test commands
- Format/lint commands with clear rollback

Manual review required:

- Write commands
- Git operations
- Package installation
- Network calls
- Deployment
- File deletion
- Credential-adjacent commands
- Shell expansion or dynamic arguments

Never auto-allow by default:

- Delete/destructive commands
- Secret access
- Deploy/publish/release
- External network writes
- Credential modification

## Verification

- Tests cover read-only safe suggestions.
- Tests cover write/network/git/manual-review classification.
- Tests cover destructive never-auto-allow classification.
