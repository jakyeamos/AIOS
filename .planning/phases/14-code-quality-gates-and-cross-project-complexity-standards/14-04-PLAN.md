# Plan 14-04: Complexity Pattern Checklist (codex-complexity-optimizer Integration)

## 2026-06-23 Baseline Update

Use `spec/success-criteria/complexity-budget.md`, `spec/success-criteria/performance-budget.md`, `spec/success-criteria/thin-display.md`, `spec/success-criteria/data-integrity.md`, and `spec/success-criteria/api-contract.md` as the canonical gate mapping for checklist categories.

## Objective

Create a local, self-contained `docs/quality/complexity-checklist.md` that captures the algorithmic complexity patterns from the codex-complexity-optimizer GitHub repo as a maintained markdown document in the AIOS repo — no external dependency, no fragile script, no false-positive noise.

## Scope

### Integration decision

The codex-complexity-optimizer repo at `https://github.com/Kappaemme-git/codex-complexity-optimizer` defines complexity review patterns. The decision (from the research doc) is:
- **Do not vendor or import the repo as a dependency.**
- **Do not create a grep-based script** — algorithmic patterns require agent/human judgment; automated grep produces high false-positive rates.
- **Create a local checklist doc** with the patterns adapted to the AIOS project context and documented clearly enough for an agent to apply.

The existing `scripts/quality-eval.sh` (Plan 10-08) covers file-level metrics (large files, import violations, dead code, shellcheck). This checklist covers the algorithmic layer that the shell script cannot.

### Checklist structure

The doc must cover 17 named patterns across three categories:

**Algorithmic Complexity Patterns (10):**
1. Nested-Loop-Scan — `for x in list: for y in list` patterns over growing data
2. Repeated-Collection-Scan — same list traversed multiple times when one pass or a lookup map suffices
3. Sort-Inside-Loop — re-sorting a list on every iteration instead of sorting once
4. Linear-Lookup-That-Should-Be-Map — `list.find()` / `array.filter()` in a loop where an ID-keyed dict/map removes the scan
5. N+1-Query — calling DB/API once per item in a loop instead of batching
6. Repeated-Object-Construction — building the same dict/object/list repeatedly in a hot path
7. Unbounded-Accumulation — appending to a growing list without bound (memory pressure)
8. Deep-Clone-In-Hot-Path — `copy.deepcopy()` / `JSON.parse(JSON.stringify())` inside a loop
9. Missing-Memoization-Boundary — expensive derivation recalculated on every call without caching
10. Repeated-Serialization/Parsing — parsing JSON/YAML/config repeatedly when it could be parsed once

**Render/UI Complexity Patterns (4):**
11. Expensive-Derived-Data-Without-Memo — computed values recalculated on every render
12. Unstable-Prop-Reference — inline object/function literals as props causing unnecessary re-renders
13. Missing-Key-On-List — list renders without stable keys causing full re-renders
14. Heavy-Computation-In-Render — sorting, filtering, or aggregating data inside the render function

**Data Access Complexity Patterns (3):**
15. N+1-In-Loop — DB query inside a loop (fetch list, then fetch details for each item)
16. Unbounded-Query — query with no LIMIT on potentially large tables
17. Missing-Index-On-Hot-Path — query on a column that is frequently filtered but lacks an index

Each pattern entry must include: pattern name, what to look for (code signature or structural cue), why it matters, and preferred remedy.

### How to Use section

Brief instructions: run through each relevant category for code just written; for each pattern found, record a hotspot using the template from `docs/quality/complexity-simplification-gate.md`; follow the fix-vs-defer rule from the gate spec.

### Attribution header

Include: "Patterns derived from codex-complexity-optimizer (https://github.com/Kappaemme-git/codex-complexity-optimizer) and the AIOS Complexity+Simplification Gate spec. This is a local copy — no external dependency."

## Standards

- Every pattern must reference a concrete code signature or structural cue, not just a generic label.
- Remedies should be specific (e.g., "build a `{id: item}` lookup dict before the loop") not vague ("use a better data structure").
- Do not add a script in this plan — the checklist as a doc is the deliverable.
