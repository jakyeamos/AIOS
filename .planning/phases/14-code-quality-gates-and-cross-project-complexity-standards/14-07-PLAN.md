# Plan 14-07: BidCamp and tm Backfill Docs

## Objective

Create complexity+simplification backfill inventories for `BidCamp` and `tm`. These are medium-risk projects with non-trivial business logic. `BidCamp` is the renamed live project for the planned `amos-saas` backfill. The docs live at `../projects/BidCamp/docs/complexity-simplification-backfill.md` and `../projects/tm/docs/complexity-simplification-backfill.md`.

## Scope

### BidCamp (`/Users/jakyeamos/projects/BidCamp`)

BidCamp is the renamed live project for the originally planned `amos-saas` backfill.

**Before writing:** Inspect source directories. Run:
- `pnpm lint`
- `pnpm tsc --noEmit`
- `pnpm knip` if wired

**High-risk areas:**
- **tRPC routers** — check for N+1 DB access patterns (calling `prisma.findUnique()` inside a loop over a list)
- **Prisma queries** — unbounded queries, missing `take`/pagination, queries on unindexed columns
- **Server Components** — data fetching patterns, expensive derived data
- **Client Components** — unstable props, missing memo, expensive render-time computation
- **Any scoring or analytics logic** — repeated aggregations, in-memory group-by patterns

### tm (`/Users/jakyeamos/projects/tm`)

**Before writing:** Inspect source directories. Run:
- `pnpm lint`
- `pnpm tsc --noEmit`

**High-risk areas:**
- **Task list operations** — filter/sort/search on in-memory task collections that could grow
- **Sync logic** — if CRDT or similar — repeated object comparison patterns
- **View derivation** — computed views recalculated on every state change without memoization

### For each project, document

Same structure as Plan 14-05/06:
- Project name and date
- Scope reviewed (actual files/dirs inspected)
- Commands attempted and outcomes
- Complexity hotspots (Hotspot template)
- Simplification hotspots (Hotspot template)
- Test gaps blocking safe cleanup
- Remediation order (P0/P1/P2)
- Risk level per hotspot
- Definition of Done for quality standard

## Standards

- If a project is large, sample the highest-risk areas first (data access, orchestration, recently changed code) and note the sampling in the scope section.
- Every hotspot references a real file path and function/line.
- "No major hotspots found in this area" is a valid observation if honest.
- Do not fix anything — record and classify only.
