# Plan 14-06: soundscape-app and portfolio Backfill Docs

## Objective

Create complexity+simplification backfill inventories for `soundscape-app` and `portfolio`. These are the two smaller/lower-risk projects in the linked project set. The docs live at `../projects/soundscape-app/docs/complexity-simplification-backfill.md` and `../projects/portfolio/docs/complexity-simplification-backfill.md`.

## Scope

### soundscape-app (`~/projects/soundscape-app`)

**Before writing:** Inspect the project root. Identify source directories (src/, lib/, components/, etc.). Run available quality commands:
- `pnpm lint` if available
- `pnpm typecheck` if available
- `pnpm test` if available

**High-risk areas to prioritize:**
- Audio file scanning and library indexing — any loops over file collections
- Metadata parsing — repeated parsing patterns
- Search/filter on large collections — linear scans that could be map-backed
- List/grid views rendering large music libraries — render performance, memoization

**Backfill doc structure:**
- Project: soundscape-app
- Date of audit: 2026-06-23
- Scope reviewed: (list files/dirs actually read)
- Commands attempted: (list commands and pass/fail/unavailable)
- Complexity hotspots: (Hotspot template entries, or "No major hotspots found in this area")
- Simplification hotspots: (Hotspot template entries, or "No major hotspots found in this area")
- Test gaps blocking safe cleanup
- Suggested remediation order (P0/P1/P2)
- Definition of Done for quality standard

### portfolio (`~/projects/portfolio`)

**Before writing:** Inspect the project root. Given a portfolio site's typical scope, the primary risks are render performance (expensive derived data, list rendering) and any data-fetching patterns.

**Note:** A portfolio site may legitimately have no major complexity hotspots. If that is the honest conclusion after inspection, record it as: "No major complexity or simplification hotspots found on this audit pass. Site scope is small and risk surface is low." This is a valid outcome — the goal is honest observation, not manufactured findings.

**Backfill doc structure:** same as soundscape-app.

## Standards

- Create `<project>/docs/` directory if it does not exist in a project.
- Every finding references an actual file path. No speculative findings.
- Record quality command output even if it is just "lint: 0 errors, 0 warnings."
- Both docs must include the Definition of Done section.
