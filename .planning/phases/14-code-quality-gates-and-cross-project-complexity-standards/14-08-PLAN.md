# Plan 14-08: Terrace Backfill Doc + Cross-Project Summary

## Objective

Create the Terrace framework backfill inventory and update the AIOS root backfill doc with a cross-project summary spanning all six external projects. Terrace gets its own plan because it is the framework underlying the agent's own skill/plan/phase execution — hotspots here affect every workflow the user runs.

## Scope

### Terrace (`/Users/jakyeamos/projects/Terrace`)

**Before writing:** Inspect the Terrace source tree. Run:
- `pnpm lint`
- `pnpm tsc --noEmit`
- `pnpm test`

Record actual output summaries from all three commands.

**High-risk areas:**
- **Execution engine** — the core loop that processes plans, phases, and skills; any loops over task graphs, plan sequences, or skill registries
- **Plan/skill dispatch** — how skills are resolved and dispatched; repeated lookups over a growing skill registry
- **Agent orchestration** — agent spawn loops, result aggregation, parallel/sequential decision logic
- **Task graph traversal** — dependency resolution, cycle detection; classic O(n²) risk for graph algorithms
- **Context compilation** — any repeated parsing of context or config files during execution

**Note on risk level:** Because Terrace is the framework the user relies on daily, every high-severity hotspot in Terrace is effectively P0 for the quality standard — it affects all downstream workflows, not just this project.

**Backfill doc structure:**
- Project: Terrace
- Framework impact note: "Terrace is the framework underlying the GSD skill/plan/phase system. Complexity hotspots here affect all agent workflows that run through it. Remediations require tests before any fix."
- Date of audit
- Scope reviewed
- Commands attempted and outcomes
- Complexity hotspots (Hotspot template)
- Simplification hotspots (Hotspot template)
- Test gaps blocking safe cleanup
- Remediation order (P0/P1/P2)
- Definition of Done
