# Plan 14-02: Pre-Check Implementation Questions

## 2026-06-23 Baseline Update

The pre-check should map each question to existing success criteria where possible. At minimum, link nested-loop and repeated-scan questions to `complexity-budget`, abstraction/readability questions to `simplicity`, test evidence to `test-quality`, and public-contract preservation to `api-contract`.

## Objective

Create `docs/quality/implementation-pre-check.md` — a standalone, short checklist of 8 questions agents should ask themselves during implementation, before the larger post-work Complexity + Simplification Gate runs. These questions catch the most common quality problems while code is still being written, not after the fact.

## Scope

Create `docs/quality/` directory if absent. Create `docs/quality/implementation-pre-check.md`.

### Checklist content

The doc must include exactly these 8 questions, formatted as a numbered list or checklist:

1. Am I creating nested loops over data that can grow?
2. Am I repeatedly scanning the same collection (find/filter/map applied multiple times on the same list)?
3. Should this data be indexed by ID/key rather than found by linear scan?
4. Am I adding unnecessary abstraction (helper that obscures rather than clarifies)?
5. Is this function doing too many things?
6. Is this code easy for a future agent or human to modify?
7. Did I add tests around the behavior I changed?
8. Did I preserve existing public contracts (function signatures, return types, exported interfaces)?

### Supporting sections

**When to apply:** During any non-trivial implementation — whenever writing a new function, extending a service, adding a new data access pattern, or wiring a new workflow step. Run the list before committing a unit of work.

**Relationship to the full gate:** The pre-check is a quick in-loop self-review (30 seconds per question). The full Complexity + Simplification Gate (Rule 12 in `config/agent-rules.md`) is the mandatory post-large-work audit. Both are required; neither replaces the other.

**Pass/fail convention:** If any question reveals a real problem — not a hypothetical — address it before completing the current unit of work rather than deferring to the gate pass.

**References:** `config/agent-rules.md` Rule 12, `docs/quality/complexity-simplification-gate.md`, `spec/success-criteria/complexity-budget.md`, `spec/success-criteria/simplicity.md`, `spec/success-criteria/test-quality.md`, `spec/success-criteria/api-contract.md`
