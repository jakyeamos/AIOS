# Plan 14-05: AIOS Backfill Hotspot Inventory

## Objective

Create `docs/backfill/complexity-simplification-backfill.md` — the AIOS-specific backfill inventory for algorithmic complexity and code simplification. This complements the existing `docs/backfill/agent-eval-backfill.md` (file-level metrics) with the pattern-level lens from the gate spec.

## Scope

### Before writing — inspect

Run `pnpm quality:eval` and record output. Then read actual source files in this priority order:

1. **services/** — scoring, context compilation, workflow orchestration, health/delta, memory layers, capabilities. These are the highest-risk complexity areas in AIOS.
2. **bin/** — ingestion scripts (`import_ai_history.py`, `cron-ingest-codex.py`, hooks), CLI wrappers. Ingestion loops and repeated file scans are the primary complexity risk.
3. **aios-ui/** — component tree, query/router layer, expensive derived data, render patterns.
4. **config/** — success criteria YAML/JSON parsing patterns, workflow registry loading.
5. **tests/** — test structure, assertion quality, coverage gaps blocking safe cleanup.

### For each area, document

- **Scope reviewed:** which files/directories were read
- **Commands run:** commands attempted and their output summary
- **Complexity hotspots:** using the `### Hotspot:` template
- **Simplification hotspots:** using the `### Hotspot:` template
- **Test gaps:** which hotspots cannot be safely remediated without new tests
- **Remediation order:** ranked list (P0/P1/P2)
- **Risk level:** per hotspot

### Hotspot template

```
### Hotspot: <short name>
- File(s):
- Category: complexity | simplification | test gap | architecture | render performance | query/data access
- Severity: low | medium | high
- Confidence: low | medium | high
- Current issue:
- Why it matters:
- Suggested remediation:
- Behavior risk:
- Tests/benchmarks needed:
- Agent-safe?: yes / no / partial
```

### Needs Deeper Audit section

List any files or modules that are too large or complex to fully audit in this pass. These are candidates for a dedicated follow-on audit before remediation.

### Definition of Done for quality standard

Include this standard:
- Complexity+Simplification Gate runs after all large-work triggers
- All hotspots in this doc are resolved or explicitly deferred with rationale
- No new O(n²) patterns added to hot paths without recorded justification
- All services over 500 lines reviewed for extraction opportunities

## Standards

- Every hotspot must reference a real file path and either a function name or line range.
- If an area has no major hotspots, record that explicitly — do not leave it blank.
- Do not fix anything in this pass. Record and classify only.
- The commands-run section must include actual output (summary counts), not just the command name.
