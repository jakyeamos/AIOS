# Quick Task 260604-sa5: Implement reusable AIOS skills harvest CLI

**Status:** Completed
**Execution mode:** Direct orchestrator execution

## Task Boundary

Build a repeatable `aios skills harvest` workflow that scans explicit project roots for agent skills, instructions, prompts, and workflow files; generates a local skills library with TMCP routing; writes audit and validation reports; initializes a generated git repository; and optionally pushes it to GitHub.

## Direct Execution Rationale

The task is non-trivial, but the implementation surface is bounded to a new service module, AIOS CLI wiring, focused tests, and a project truth update. TDD and local validation provide stronger control than subagent handoff for this compact filesystem workflow.

## Plan

1. Add failing tests for scanner/classifier/generator behavior and CLI wiring.
   - Files: `tests/test_skills_harvest.py`, `tests/test_aios_cli.py`
   - Verify: targeted pytest failures show missing module/command behavior.

2. Implement the harvester as a narrow Python service and wire `aios skills harvest`.
   - Files: `services/skills_harvest.py`, `services/aios_cli.py`
   - Behavior: dry-run, report-only, tier-aware source classification, conceptual skill consolidation, TMCP generation, validation, git init/commit, optional GitHub push, JSON/human summaries.

3. Run the workflow and validate durable output.
   - Commands: targeted pytest, ruff, dry-run harvest, real harvest, generated validation, git status checks.
   - Artifacts: generated skills repo, `skills.tmcp/`, audit reports, manifest, local commit, GitHub push instructions.

## Result

- `aios skills harvest` now scans explicit local project and agent roots and writes a generated skills library without modifying sources.
- The harvester separates `project_authoritative`, `personal_agent`, `local_agent_config`, `plugin_reference`, `history_reference`, and `reference` tiers.
- Broad local harvest found 2,834 candidates and consolidated 1,694 reusable skill candidates into 99 canonical skill groups.
- Active TMCP generation uses 1,539 project/personal/global-config sources while preserving reference-tier material with provenance.
- Generated repo: `skills-library/`
- Generated repo commit: `641e0b0 Initial AIOS skills library harvest`
- GitHub push was not completed because network approval for `gh repo view` was rejected; exact push commands are available in the CLI output and README.

## Acceptance Gates

- `aios skills harvest --roots ... --out ... --dry-run --json` does not write an output repo.
- Real harvest writes `README.md`, `skills/`, `instructions/`, `workflows/`, `skills.tmcp/`, `audit/`, `skills.lock`, and `manifest.json`.
- Every generated skill has provenance.
- Every source candidate is imported, transformed, skipped, or explicitly reported.
- Secret-like content is redacted or skipped and reported.
- TMCP router and manifest links resolve.
- The generated repo is locally committed.
- GitHub push is attempted when requested and does not block local completion if unavailable.
