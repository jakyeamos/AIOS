# AIOS Storage Contract

This document is the authoritative definition of what lives where, who may write it,
and what each store is responsible for. Update this when the architecture changes.

---

## The Four Stores

| Store | Path | Authority domain |
|---|---|---|
| **SQLite** | `~/AIOS/data/aios.db` | All machine-readable operational state |
| **CTS Graph Store** | `~/AIOS/data/cts/` | Per-repo code topology indexes (local-only) |
| **Vault** | `AIOS_VAULT_ROOT` (`~/projects/Vaults/Command-Center/` by default, resolved through `services/path_resolution.py`) | All human-readable content and human-authored knowledge |
| **Staging** | `~/AIOS/staging/` | All content in transit awaiting review or promotion |

Code truth lives in `~/Projects/*/` git repos. AIOS observes code; it does not own it.

CTS graph indexes are local-only operational artifacts. They can be rebuilt from source code and
must never be treated as canonical source-of-truth over the code repository itself.

---

## SQLite — Authoritative for operational state

### What agents may write automatically (no human gate)

- `sessions` — created and closed by hooks
- `tool_events` — all hook events logged here
- `prompts_used` — every prompt logged at submit time
- `artifacts` — file write/edit events captured by post-tool hook
- `bug_log` — Bash errors auto-captured by post-tool hook
- `patterns` with `state='notice'` and `status='candidate'` — auto-created from tool errors and prompts
- `pattern_events` — confirmation/contradiction trail, written by hooks
- `workflow_metrics` — performance and throughput tracking
- `ai_history_imports` with `status='staged'` — import pipeline writes here; promotion requires human

## CTS Graph Store — Authoritative for derived code topology only

### What belongs here

- Per-repo `graph.db` SQLite files under `~/AIOS/data/cts/<repo_hash>/`
- Derived structural nodes/edges, confidence scores, staleness flags, and FTS indexes
- Optional benchmark outputs under `~/AIOS/data/cts/eval_results.json`

### Guardrails

- CTS data is derived from source code and may be stale or low-confidence.
- CTS data must not be synchronized to remote repos or committed to source control.
- CTS never writes to project source files; it only reads code and updates local index files.

### What requires human approval before writing/updating

- `patterns.human_approved = 1` — only set via `review_app.py` after human approves
- `patterns.state = 'rule'` — only reachable via human approval in review UI
- `ai_history_imports.status = 'promoted'` — only set via `promote-imports.sh` after human review
- `projects.obsidian_path` — path to vault project note; set manually or on registration

### Cross-store pointers (must be kept in sync)

- `sessions.handoff_path` — path to vault handoff file; written by `hook-stop.py` at close
- `projects.obsidian_path` — path to vault project note; set manually or on registration (column already existed, now being actively populated)
- `patterns.vault_path` — path to wiki stub or entry; written by `promote-patterns.py`

## Vault — Authoritative for human-readable and human-authored content

### What belongs here

- **Session handoffs** (`02 AI OS/02 Session Handoffs/`) — written by agent at session close;
  contains narrative prose, open actions, decisions. Source: claude-mem or hook-stop.
  DB pointer: `sessions.handoff_path` (written at close).

- **Project notes** (`03 Projects/*.md`) — human-maintained; "Current Focus" section is
  operationally load-bearing (read by session-start hook). DB pointer: `projects.obsidian_path`.

- **Wiki entries** (`06 Knowledge/Wiki/`) — human-authored content only. Stubs from
  `promote-patterns.py` land in `staging/knowledge-drafts/` first; promotion to this
  folder requires human authorship of the body.

- **Domain files** (`06 Knowledge/Domains/`) — auto-generated from DB queries by
  `build-domain-files.py`. Read-only for agents. Do not hand-edit; they will be
  overwritten on next maintenance run.

- **Self notes** (`06 Knowledge/Self/`) — human-authored only, never agent-written.
  Contains methodology, principles, working preferences. Max ~10 notes.

- **Templates** (`07 Templates/`) — canonical frontmatter schemas. Agents must read
  these when generating vault-destined content.

### What agents may write to vault automatically

- Session handoffs (narrative, follows Session template)
- Session packet files (`~/AIOS/logs/session_packet_*.md`) — ephemeral, auto-cleaned
- Lab reports (`02 AI OS/05 Tooling/lab-report-*.md`) — auto-generated by pipeline
- Domain files (`06 Knowledge/Domains/`) — auto-generated from DB; not curated content

### What agents must NOT write directly to vault

- `06 Knowledge/Wiki/` — stubs go to `staging/knowledge-drafts/` first
- `06 Knowledge/Self/` — human-authored only
- `03 Projects/` — human-maintained project notes
- `07 Templates/` — only changed deliberately

## Staging — Authoritative for content in transit

### What lives here

| Path | Contents | Promoted to |
|---|---|---|
| `staging/ai-history/raw/` | Raw Claude/Codex exports (55.8GB+) | `staging/ai-history/ready/` → vault |
| `staging/ai-history/ready/` | Processed imports, awaiting review | `ai_history_imports.status='promoted'` + vault |
| `staging/knowledge-drafts/` | Auto-promoted pattern stubs, need body | `06 Knowledge/Wiki/` after human authors body |
| `staging/pattern-candidates/` | Reserved for future use | — |
| `staging/session-handoffs/` | Session handoff files (active store) | Referenced by `sessions.handoff_path` |

### Promotion rules

- Nothing in staging counts as canonical knowledge.
- `staging/knowledge-drafts/` content must not be returned by retrieval until promoted to vault.
- AI history items: use `promote-imports.sh` after human review.
- Wiki drafts: human must author body, then manually move file to `06 Knowledge/Wiki/`.

## Tier Summary

| Tier | Authority | Content type | Agent writes? |
|---|---|---|---|
| Raw events | `aios.db` | sessions, events, prompts | Yes, always |
| Bug tracking | `aios.db` | bug_log | Yes (auto-capture) |
| Pattern candidates | `aios.db` | patterns state=notice/hypothesis | Yes (auto-create) |
| Approved rules | `aios.db` active_rules VIEW | state=rule, human_approved=1 | No — human gate |
| Code intelligence | `~/AIOS/data/cts/` | derived topology, confidence, staleness | Yes, local operational artifacts only |
| Wiki / knowledge | Vault `06 Knowledge/Wiki/` | authored entries | No — staging gate |
| Handoff notes | Vault + `sessions.handoff_path` | narrative handoffs | Yes (hook-stop) |
| Project context | Vault + `projects.obsidian_path` | project notes | No — human-maintained |
| Personal corpus | `Personal-Corpus/` vault | AI history highlights | Deferred |
| Self / principles | Vault `06 Knowledge/Self/` | methodology, principles | No — human only |

## Failure modes to watch for

- **Silent vault path change** — if a handoff or project note moves without updating the DB pointer,
  session packets will silently degrade. AIOS resolves `AIOS_VAULT_ROOT` first and defaults to
  `~/projects/Vaults/Command-Center/` through `services/path_resolution.py` and the
  `bin/aios_paths.py` CLI wrapper used by shell scripts. The legacy `~/Vaults/Command-Center/`
  path is only a compatibility fallback when the canonical path is absent; `vault-lint.py`
  should detect dead paths and stale pointers.
- **Stale INDEX.md** — domain INDEX files must reflect DB state, not markdown file counts.
  `build-domain-files.py` queries DB directly; do not rely on file-system counts.
- **Wiki stubs as canonical knowledge** — stubs in `staging/knowledge-drafts/` must never be
  included in retrieval. The `require_human_curated: true` retrieval gate enforces this.
- **Personal-extract queue poisoning** — `extract-personal-patterns.py` runs daily.
  Patterns require ≥2 distinct sessions or an explicit trigger to persist. Low-volume
  signals are discarded immediately, not queued.
